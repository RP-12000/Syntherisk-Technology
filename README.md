## 跑起来

```powershell
# 1. 建环境、装依赖（只装进项目自己的虚拟环境）。这台电脑上已经装好了，换电脑时才需要
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.lock.txt

# 2. 启动。在 PyCharm 里直接运行 main.py 也一样（解释器选 .venv）
.venv\Scripts\python.exe main.py

# 3. 跑测试
.venv\Scripts\python.exe -m pytest
```

整个项目只有一个环境 `.venv`（Python 3.12，这台电脑是 3.12.10），后端和 AiZynthFinder 都装在里面，在 PyCharm 里解释器就选它。
`requirements.lock.txt` 是实际装着的精确版本（211 个包），照它装出来的环境和这台电脑上一样；
`requirements.txt` 只列直接依赖和版本范围，升级依赖时才用。

因为和 AiZynthFinder 装在一起，后端用的是它要求的旧版本：**NumPy 1.26（低于 2）和 RDKit 2023.9**，Python 也不能高于 3.12。
以后给后端加别的包（比如 M8 的产率模型）时，要挑和这两个旧版本兼容的；装完运行一下 `.venv\Scripts\python.exe -m pip check`，
并且确认 pyarrow 还是 25.0.0（它被别的包带着升级的话，AiZynthFinder 会起不来，见下面“踩过的坑”）。

最初是在 Python 3.14、新版 NumPy 和 RDKit 上开发的，另有一个单独的环境装 AiZynthFinder；2026-10-11 合并成现在这一个。
合并以后全部测试、服务启动、真实引擎的完整分析都重新跑过，先例库也用这个环境重新导了一遍
（新旧 RDKit 算出来的指纹和反应中心抽查一万条完全相同，只有约 7% 的结构写法、万分之一的反应编号不同）。
联网的接口（PubChem、OPSIN、Crossref）没有重新调，它们用的 httpx 版本没有变。

启动后打开 <http://127.0.0.1:8000/docs>，能看到全部接口并直接试调。

什么都不配置也能跑：数据存在本地 SQLite（`var/syntherisk.db`），长任务在进程内的线程池里跑，
逆合成用内置的演示路线，不调大模型。要接真的引擎和数据，照着 `.env` 写一份 `.env`。
这台电脑上已经有一份 `.env`，把逆合成指到了 AiZynthFinder（见下面“这台电脑上已经接好的”）。

想先看个完整例子：在 `.env` 里填好 `DEMO_USER_EMAIL` 和 `DEMO_USER_PASSWORD`，然后

```powershell
.venv\Scripts\python.exe -m syntherisk.cli seed-demo   # 建演示课题组、账号和几样库存
.venv\Scripts\python.exe -m syntherisk.cli status      # 看各模块现在接的是什么
```

## 技术选型

PPT 写明的：FastAPI、PostgreSQL、Redis + Worker + SSE、AiZynthFinder、RDKit、OPSIN、PubChem。其余按主流方案选的：

- **数据库**：SQLAlchemy 2。本地默认 SQLite，生产设 `DATABASE_URL` 换 PostgreSQL，代码不用改。
  表是启动时自动建的；现在没有迁移工具，以后要改已有的表结构时再加（比如 Alembic）。
- **任务队列**：自己写的一个很薄的队列（`taskqueue.py`）。本地在进程内跑；设 `QUEUE_BACKEND=redis` 后由 `python -m syntherisk.worker` 从 Redis 取任务。没有用 Celery 或 RQ，因为它们在 Windows 上不好用。
- **进度推送**：Worker 把进度写进数据库，SSE 接口从库里读，所以 API 和 Worker 分开部署也能推进度。
- **登录**：邮箱 + 密码，密码用 scrypt 哈希，登录后发 JWT。
- **加密**：客户库存、目标结构、分析结果、实验回填、报告文件都在应用层加密（Fernet）后再存。按结构匹配库存用的是“盲索引”，不用解密整张表。
- **大模型**：`syntherisk/llm/` 是唯一知道厂商的地方。Claude 走 Anthropic 官方 SDK，其他厂商走兼容 OpenAI 的 HTTP 接口。换厂商只改 `.env`。
- **报告**：ReportLab（PDF）、python-docx（Word）、openpyxl（Excel）。

## 这台电脑上已经接好的

下面两样在这台电脑上已经装好、接上、跑过。这些文件都很大，不进代码仓库；换一台电脑要照着重做一遍。

### AiZynthFinder（M3 逆合成搜索）

AiZynthFinder 4.4.1 和后端装在同一个环境 `.venv` 里。后端每次搜索另起一个进程去跑它（用的是同一个 Python）：
一次搜索要占 3.3 GB 内存，主要是 1700 万条在售清单，跑完随进程一起还给系统；用户取消分析时也能直接结束它。
公开模型和在售清单在 `data\external\aizynth\`，`.env` 里有一行 `AIZYNTH_CONFIG` 把后端指到它们。
`python -m syntherisk.cli status` 里 M3 一项显示 `aizynthfinder` 和 `"ready": true` 就是接好了；
想临时换回内置的演示路线，在 `.env` 里加一行 `M3_ENGINE=demo`。

实测（这台电脑）：一次搜索加上加载模型大约 25–60 秒。
默认搜 400 轮：布洛芬搜 100 轮找不到完整路线，400 轮能找到十几条。

换一台电脑从头装：照上面“跑起来”装好环境以后（`requirements.lock.txt` 里已经包含 AiZynthFinder），再下载公开模型：

```powershell
New-Item -ItemType Directory -Force data\external\aizynth
.venv\Scripts\download_public_data.exe data\external\aizynth
```

然后在 `.env` 里写上 `AIZYNTH_CONFIG=data\external\aizynth\config.yml`。

踩过的坑：

- 要照 `requirements.lock.txt` 装，不要只 `pip install aizynthfinder`。那样 pip 会装上只认 NumPy 2 的 pyarrow 26，
  而 AiZynthFinder 要求 NumPy 低于 2（PPT 里提过的那个冲突），一导入就报 `pyarrow requires NumPy 2.0 or newer, found 1.26.4`。
  pyarrow 要用 25.0.0；也不要装太旧的，17.0.0 会让程序在加载模型时直接崩溃（它自带的旧版 `msvcp140.dll` 和 onnxruntime 冲突）。
- 下载模型前要先建文件夹（上面第一行）。下载工具不会自己建，没有文件夹会报 `FileNotFoundError`。下载约 0.8 GB。
- 模型不在 AiZynthFinder 的 GitHub 仓库里，不用到那个页面上找文件：下载工具是从 Zenodo 和 Figshare 取这 6 个文件的
  （两个单步模型和各自的模板、一个过滤模型、一份 ZINC 在售清单），取完在同一个文件夹里生成 `config.yml`。
- `config.yml` 里写的是这 6 个文件的完整路径。项目文件夹改了名或者挪了位置，要把里面的路径跟着改掉。
  换电脑时也可以不重新下载：把整个 `data\external\aizynth` 文件夹拷过去，再改 `config.yml` 里的路径。
  （重新运行下载工具也会生成新的 `config.yml`，但它每次都把 6 个文件重新下载一遍。）

### USPTO 先例库（M5 文献先例）

Lowe 整理的美国专利反应数据集（CC0 许可），已经全量导入 `var\syntherisk.db`：1,750,279 条，数据库约 1.5 GB。
其中 1,712,910 条按原子映射算出了“反应中心”；剩下的 2% 没有键的变化（成盐、提纯这类记录，或者原始数据的映射没有标出变化），只当旁证用。
原始文件在 `data\external\uspto\`。后端第一次分析时要把先例库的索引读进内存（约 13 秒、700 MB），之后每一步检索约 0.1 秒。
运行 `python -m syntherisk.cli status` 能看到这两个数（`precedents` 和 `precedents_with_center`）；
后一个是 0 的话，说明库是加入反应中心之前导入的，要重新导一遍。重新导入以后不用重启后端，它下次分析时会自己重新加载。

换一台电脑时最省事的办法是不重新导：在后端没有运行的时候，把 `var\syntherisk.db` 这一个文件拷到那台电脑项目的 `var` 文件夹里。
先例库不加密，那台电脑用它自己的密钥也读得出来（不用拷 `var\dev_secrets.json`）。要注意这个文件里还有账号、库存、分析这些数据：
现在这台电脑的库里只有先例和内置在售试剂，没有任何账号，可以直接给；以后库里有了自己的数据，就不要这样整个拷给别人了。

换一台电脑从头导：

1. 打开 <https://doi.org/10.6084/m9.figshare.5104873>，下载里面的 `1976_Sep2016_USPTOgrants_smiles.7z`（75 MB）。
2. 解压（7-Zip，或者 Windows 11 自带的“全部解压缩”），把解压出来的 `.rsmi` 文件放进 `data\external\uspto\`。
3. 在项目根目录运行：

   ```powershell
   .venv\Scripts\python.exe -m syntherisk.cli load-precedents --source uspto --replace --file data\external\uspto\1976_Sep2016_USPTOgrants_smiles.rsmi
   ```

   默认用一半的 CPU 核同时算，这台电脑（10 个进程）全量用了半小时左右。想先试跑，加 `--limit 20000`。
   导完会报告有多少条算出了反应中心（原始数据带原子映射才算得出）。以后如果改了反应中心的算法
   （`m01_structure.py` 里 `_center_from_mols` 那一段），要用这条命令重新导一遍；只改归并规则（`center_class`）不用。

**不要只导一部分就拿来用。** 先例库里只要有数据，查不到先例的步骤就会被判成“仅模型预测”并且扣分；
只导了 2 万条的时候，几乎每一步都会被这样误判。要么全量导入，要么保持空的（那时证据等级显示“未评估”）。

## 还需要你来做的

1. **大模型的 API key（M2、M11、M12）**。选定厂商后写进 `.env`。

2. **PostgreSQL 和 Redis**。本地开发不需要；上服务器时装好，改 `DATABASE_URL`、`QUEUE_BACKEND`、`REDIS_URL`。
   这两种配置的代码都写了，但这台电脑上没有装这两个服务，所以没有在它们上面验证过。

3. **请懂化学的人复核危害分类表**。`data/compounds.csv` 里 114 种试剂的 GHS 危害编码最初是我凭记忆写的，
   后来全部和 PubChem 逐个对过一遍，按结果改了 50 行（规则见下面“危害分类取哪个来源”）。
   这只是机器对机器，没有人复核过，所以 `reviewed` 列仍然全是 0，报告里也会提示“还没有经过复核”。
   复核完一行，把它的 `reviewed` 改成 1。以后往表里加试剂、或者想再对一遍，运行：

   ```powershell
   .venv\Scripts\python.exe -m syntherisk.cli check-hazards
   ```

   它查得很慢（三秒一次请求，全表约十五分钟），只列出表里和 PubChem 不一致的行；中途被限流会停下，并告诉你从哪里接着查。
   下面这几种是我有意保留的不同，因为 PubChem 上的分类对应的是另一种形态：

   | 试剂 | 表里按什么算 | PubChem 上是什么 |
   |---|---|---|
   | 盐酸 | 水溶液（腐蚀、刺激呼吸道） | 氯化氢气体（另有“吸入会中毒”） |
   | 甲醛 | 福尔马林溶液（吸入会中毒） | 甲醛气体（吸入致命） |
   | 氨水 | 保留“刺激呼吸道” | 没有这一条 |
   | 镁屑、锌粉 | 镁屑、稳定化的锌粉 | 会自燃的金属粉末 |
   | 雷尼镍、钯碳 | 干的催化剂（会自燃 / 易燃） | 金属镍、金属钯 |
   | 苯基溴化镁 | 保留“遇水放出可自燃的气体” | 没有这一条 |
   | 三丁基氢化锡 | 保留生殖毒性（三丁基锡类化合物的统一分类） | 没有这一条 |
   | 间氯过氧苯甲酸 | 有机过氧化物 | 只有“易燃、腐蚀”，对不上 |
   | 二氯甲烷 | 多一条“可能造成昏昏欲睡” | 差一点不到 30% |

   另外有两种（碘化亚铜、氢化钠）PubChem 上查不到分类，表里的还是我原来写的。

   有一段还差最后一步：表里从甲苯到氯乙酸乙酯这 30 来种，是在这条命令定型之前对的（那时企业申报的比例还没有折算）。
   我想用定型后的命令把全表再对一遍，查到第 17 种时 PubChem 又限流了；前 16 种的结果和上表一致。等限流解除后运行
   `check-hazards --start-from toluene`，这一段可能会多列出几行（比如几种钯催化剂），需要看一下再决定改不改。

4. **请懂化学的人回测证据等级**。“同类反应”现在按原子映射比反应中心来认（做法和我定的几条归并规则见下面
   “几处和你预想的可能不一样的地方”），原先“反应不同却被当成先例”的错判是这样解决的。
   我用 AiZynthFinder 给 20 个常见分子提出的 279 个真实拆分，把新旧两种办法逐条对比过（结果见同一节）。
   但这仍然是我一个人看的，PPT 附录里说的“用历史案例回测、化学家盲评”还没有做。回测时请特别留意这几处已知的局限：

   - **小分子吃亏**。“底物像不像”比的是产物结构，分子越小，换一个取代基相似度掉得越多。
     比如苯基溴化镁和乙醛得到 1-苯乙醇，库里同类反应最像的先例只有 0.66，够不上“高相似先例”（要 0.7）。
   - **不看选择性，也不看条件**。“分子里另有一个乙酸酯时水解甲酯”这样的步骤，只要库里有相近底物的甲酯水解，就会判成高相似先例。
   - **引擎把溶剂、试剂写成反应物的步骤，按它实际代表的转化来评**。比如“二氯甲烷 + 苯甲醛 → 氧化苯乙烯”
     （专利数据里的错标留在模型里的痕迹）会按“醛接上一个碳成环氧”去找先例，找到的是锍叶立德的做法，等级是高相似先例。
     转化本身确实有先例，但写出来的那个“反应物”是错的，要看列出的先例才知道实际怎么做。
   - **没有原子映射的步骤仍然按指纹比**（内置的演示路线、以后手工录入的路线），那种办法的毛病都还在。
   - “文献直接报道”不受这次改动影响（那是按反应物和产物完全一致来判的）。

5. **化学上要复核的其他初稿**（都在 `data/` 下，改完重启即可，不用改代码）：

## 几处和你预想的可能不一样的地方

- **路线长短不直接影响路线分**。PPT 的公式是“0.6 × 各步平均分 + 0.4 × 最弱一步”，步数不在里面。所以在演示数据上，
  不加任何限制时，6 步的 Boots 路线（81.1 分）排在 4 步的格氏路线（77.8 分）前面。要不要加一项步数或总产率，需要你们定。
- **没有数据的维度不计分**，而不是按 0 分算，也不按满分算。比如先例库没导入时，文献依据这 30% 不参与，其余权重按比例放大；
  没有文献产率的步骤，产率这 10% 也不参与。界面上要把“未评估”和“没找到”区分开。
  接上 AiZynthFinder 以后这一条变得很要紧：它只给反应物和产物，不给试剂和条件，中间体也大多查不到危害数据。
  所以“用到的物质都查不到危害”时安全一项不评分，“不知道试剂和条件”时操作一项不评分（显示“操作 未评估”）。
  一步里有数据的项目太少（权重加起来不到 30%）时，这一步标为依据不足、算低置信度，并且不计入路线分。
- **AiZynthFinder 给的路线要靠先例来把关**。公开模型会给出一些看着奇怪的步骤（比如把乙酸、二甲基亚砜写成反应物，
  那是专利数据里试剂被当成反应物留下的痕迹），反应名字也是我按官能团变化猜的，认不出来的叫“官能团转化”或“片段连接”。
  每一步靠不靠谱，要看它的证据等级和列出来的先例，这正是这个产品要做的事。
- **危害数据会直接影响排除结果**，所以演示的结论跟着数据走。布洛芬的例子里：
  勾“排除剧毒”，Boots 路线也会被排除，因为第 2 步的氯乙酸乙酯被多数企业申报为“皮肤接触致命”（H310），只剩格氏路线；
  勾“排除致癌、致突变、生殖毒性物质”，格氏路线反而被排除，因为硼氢化钠按现行分类有生殖毒性（H360F）。
  被排除的路线都会留在结果里并写明是哪一步、哪个物质、哪条危险性说明。
- **危害分类取哪个来源，是我定的规则**：欧盟统一分类，加上至少占全部企业申报 30% 的分类，同一种危害取最重的一档
  （阈值是 `scoring.toml` 里的 `pubchem_min_share`）。PubChem 同一个页面上还有日本 NITE 的分类，没有采用，
  因为它的口径宽得多（比如把乙醇列为致癌，指的是饮酒），直接用会把常见溶剂都筛掉。查不到分类的物质标“没有危害数据”，不当作安全。
- **证据等级里的“相似度”怎么算，是我定的**。PPT 给的阈值是“相似度 ≥ 0.7 算高相似先例”。用最常见的 Morgan 指纹算，
  很接近的同系物也只有 0.48–0.67，0.7 基本达不到，所以我换了一种指纹，阈值仍是 0.7。
- **“同类反应”怎么认定，也是我定的**。高相似先例要同时满足两条：底物像，并且是同一种反应。后一条是这样判断的：
  AiZynthFinder 给的每一步、USPTO 的每条专利反应都带原子映射（每个原子从哪来、到哪去），据此能列出这一步到底
  成了哪些键、断了哪些键、掉下去的是什么基团，这就是“反应中心”。两步反应的反应中心一模一样，才算同类反应；
  成的键一样、掉下去的基团不一样的（先例用酰氯，这一步用羧酸；先例脱 Cbz，这一步脱 Boc）只算“相关反应”，
  给的分很低，也不借用它的产率和试剂。证据卡的 `center` 字段就是这一步的反应中心，比如
  `F:C.acyl~N:1|L:C.acyl~Cl:1` 读作“酰基碳和氮之间成了一根单键，酰基碳上掉了一个氯”。
  哪些差别忽略不计，是我凭常识定的，化学家可以改（`m01_structure.py` 里的 `center_class`，改完重启即可，不用重新导数据）：

  | 算同一类 | 不算同一类 |
  |---|---|
  | 掉下去的是氯、溴、碘、磺酸酯（甲磺酸酯、对甲苯磺酸酯、三氟甲磺酸酯） | 掉下去的是氟（只能做亲核取代，不能偶联） |
  | 芳环上的羟基、氨基和烷基上的 | 酰胺的氮和胺的氮；羧酸的羟基和醇的羟基 |
  | 甲酯、乙酯这类普通烷基酯的水解 | 叔丁酯、苄酯的脱除；脱 Boc、脱 Cbz、脱乙酰基也各算一类 |
  | 试剂只给出一个原子时，不看是哪种试剂：溴素和 NBS 的溴代，氯化亚砜和草酰氯制酰氯 | 溴代和氯代 |
  | 酚、醇、硫醇、酰胺氮、芳环氮的甲基化，和它们同别的卤代烷的烷基化 | 胺的 N-甲基化（也可能是甲醛还原胺化）、羧酸成甲酯（也可能是和甲醇酯化），各单独一类 |
  | 醛的羰基和酮的羰基 | 羧酸、酯、酰胺、酰氯的羰基 |

  这是把原来按指纹比的办法换掉以后的做法。指纹比的是“反应前后各种原子多了几个、少了几个”，不看哪个原子接到了哪里，
  所以会把“乙酰胺 + 对溴苯酚 → 对乙酰氨基酚”（酰胺的 N-芳基化）当成苯胺酰化的同类；一条不靠谱的阿司匹林路线
  （2-氟苯甲酸和乙酸成酯）也曾靠着“水杨酸乙酰化”的专利排到第一。指纹现在只用在没有原子映射的步骤上。

  我用 AiZynthFinder 给 20 个常见分子（阿司匹林、布洛芬、利多卡因、普萘洛尔等）提出的 279 个拆分，把两种办法逐条对比过：
  44 步是文献直接报道，两种办法没有区别；其余 235 步里，173 步等级不变，21 步变严，41 步变宽。
  - 变严的，比如利多卡因的“二乙氨基乙酰氯 + 2,6-二甲基苯胺”：指纹找到的“高相似先例”其实是另一个反应
    （氯乙酰苯胺和胺的烷基化），按反应中心只认氯乙酰氯酰化 2,6-二甲基苯胺的那几篇专利，降为低相似先例。
    没有活化的氟苯和苄胺的取代、“硝酸 + 苯酚一步得到对氨基苯酚”也都降了级。
  - 变宽的，比如苄基氯、甲磺酸苄酯和叠氮化钠：库里同一个产物的先例用的是苄基溴，指纹认不出是同类，现在认得出。
    五氯化磷制苯甲酰氯、双氧水环氧化苯乙烯同理（试剂不同，转化相同）。
  - 每一步的检索也从约 0.9 秒降到 0.1 秒左右。
- **管制化学品分两级**。勾“排除易制毒 / 管制化学品”只排除管得严的那一级（中国第一、二类，美国 List I，加拿大 Class A）；
  甲苯、丙酮、盐酸这类一般管理的只做提示，否则几乎所有路线都会被排除。
- **AiZynthFinder 找的不一定是化学家心目中的最优路线。** 它的公开模型是从美国专利里学的 42,554 条反应模板，每一步只试模型打分最高的 50 条。
  它能表示“两分子同一原料”的反应（2X + Y → Z），但专利数据不写化学计量，这种模板只有 70 条，所以对称的分子大多被拆成一步一步来。
  实测（2026-10-18）1,4-二苯甲基苯：合理的傅-克烷基化拆法（三苯甲烷 + 二苯甲醇）在模型里排第 253 位，根本不会被试到，
  结果给出的是七八步的格氏、脱氧路线。我们的评分只能在它给出的路线里排先后，补不了它没找到的路线。
- **证据卡上期刊论文排在专利前面**，两种文献分开检索、各自最多列 8 条。但现在先例库里全是 USPTO 专利，期刊论文要另外导入数据才会出现。
